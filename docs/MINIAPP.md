# Telegram mini-app «Агенты»

Управление агентами из Telegram: карточки, задачи, переписка, отправка указаний.

## Как работает

Страница: `miniapp/index.html`. Данные берутся с `agent-board`:

| Запрос | Путь |
|---|---|
| список проектов | `GET /api/projects` |
| состояние проекта | `GET /api/project/{name}` |
| указание команде | `POST /api/say` |

**База API настраивается один раз** в localStorage браузера mini-app:

```js
localStorage.setItem('agentboard_api', 'http://<хост>:9121');
```

Пустое значение = тот же origin (когда страницу раздаёт сам `agent-board` на `/miniapp`).

## Три способа развернуть

**1. Локально, на этой машине** — `agent-board` уже отдаёт страницу:

```
http://127.0.0.1:9121/miniapp
```

**2. Статикой в GitHub Pages** — страница уже запушена:

```
https://italeex.github.io/web-demos/demos/miniapp/
```

Но API живёт на этой машине, поэтому в localStorage нужно задать адрес:
`http://<внешний-адрес>:9121`. Для Telegram нужен **HTTPS** — значит нужен туннель
или reverse-proxy с сертификатом.

**3. Через отдельный домен** — положить `miniapp/index.html` рядом с
`agent-board` на любом хостинге и проксировать `/api/*` на `agent-board`.

## Подключение к боту

В `@BotFather`:

```
/newapp → выбрать бота → задать URL (https://<домен>/miniapp/)
```

Кнопка открывает mini-app. Внутри страница использует `Telegram.WebApp.ready()`
и рисуется в тёмной теме под интерфейс Telegram.

## Что умеет

- **Таблетки проектов** — переключение, счётчик «работает/всего», цвет точки статуса.
- **Карточки агентов** — имя, цвет статуса, число задач в работе, фрагмент текущей задачи.
  Тап открывает список задач агента.
- **Вкладки** — Задачи (по выбранному агенту), Переписка (канал проекта), Все (список задач).
- **Поле указания** внизу — отправляет сообщение в канал команды и будит лидера.

## Ограничения

- Mini-app работает в браузере Telegram: **CORS обязателен**. В `agent_board.py`
  заголовки `Access-Control-Allow-Origin: *` уже проставлены.
- Для Telegram нужен HTTPS. Локальный `127.0.0.1:9121` из телефона недоступен.
- Отправка указания не требует авторизации в текущей реализации — **это дыра**:
  любой, кто откроет URL, сможет писать в канал. Перед публикацией наружу нужно
  закрыть доступ: токен в заголовке `X-Auth` + проверка на сервере.
