# Архитектура

## Слои

```
оператор
   │  пишет в канал (TUI / mini-app / Telegram)
   ▼
командный канал Agora ── задача в статусе scheduled, комментарии с префиксом [agora:msg]
   │
   ▼
лидер (профиль Hermes) ── heartbeat каждые N минут
   │  поднимает motion → команда обсуждает и голосует
   │  принятое решение → action_items → задачи
   ▼
диспетчер Hermes ── раздаёт задачи воркерам по ролям
   │
   ▼
воркеры (профили Hermes) ── свои SOUL.md, своя память, свои скиллы
   │
   ▼
vault/Агенты/ ── журнал проекта, предложения, реестр денег
```

## Почему профили, а не промпты

Каждый воркер — **отдельный профиль Hermes** со своим SOUL.md и своей `state.db`.
Это даёт три вещи, которых не даёт промпт внутри одного контекста:

1. **Память переживает сжатие контекста.** У воркера своя база сессий.
2. **Изоляция.** Воркер не видит чужой переписки, кроме канала проекта.
3. **Настоящий найм.** Новый воркер — новый профиль, а не строчка в инструкции.

Разделение ролей: `architect`, `developer`, `reviewer`, `tester`, `devops`,
`researcher`, `writer`, `sourcer`, `leader`.

## Канал — единственное место, где виден разговор

Каждый проект имеет **командный канал**: постоянная задача в статусе `scheduled`.
Она никогда не закрывается, в неё пишут все.

- Агенты: `agora_message(project, type, content, target)`.
- Лидер: `agora_read_chat(project, limit)`.
- Оператор: тоже в `[agora:msg]`, иначе лидер не прочитает.

**Почему префикс `[agora:msg]` важен.** `agora_read_chat` парсит только структурные
сообщения. Сырой комментарий в базе существует, но для лидера его нет. На этом
уже терялись ответы оператору — поэтому формат зафиксирован в коде панели и в TUI.

## Доски задач

У каждого проекта своя доска (`tenant` в канбане): `agora-crypto-earn`,
`agora-demo-sites`. Задачи связаны через `task_links`: дочерняя не начнётся,
пока родительская не закрыта.

Статусы: `scheduled` (канал), `running`, `ready`, `todo`, `blocked`, `done`,
`archived`.

**Важно:** при завершении проекта Agora удаляет его задачи вместе с каналом.
Проект, помеченный `completed`, теряет канал — и оператор видит
«командный канал проекта не найден». Лечится `update_project(reactivate=True)`.

## Гейт на изменение системы

Агенты могут менять **работу** (задачи, файлы, страницы) и не могут менять
**систему** (скиллы, cron, плагины) без согласования.

```
агент пишет JSON в vault/Агенты/Предложения/
        ↓
лидер на heartbeat: endorsed = true/false + причина
        ↓
оператор в TUI: a — утвердить, r — отклонить
        ↓
только теперь: скилл создан / cron запущен
```

Причина двухуровневой схемы: лидер знает контекст задачи и отсеивает предложения,
которые не нужны; оператор отвечает за ресурсы и риск. Одного уровня мало.

## Деньги

Три рельса, каждый проверяется живым запросом до начала работы:

| Рельс | Проверка | Оплата |
|---|---|---|
| POIDH | `bounties.fetchAll` + чтение контракта `claimCounter` | крипта на кошелёк |
| Verdikta | исходник `BountyEscrow.sol` через sourcify | крипта |
| Сайты на заказ | письмо → демо → заказ | карта, чек самозанятого |

Стандарт доказательства выплаты (принят командой): выплата доказана, если есть
**наша** транзакция со `status = 0x1`, событие `Withdrawal` с нашим адресом,
`pendingWithdrawals(наш) = 0` после неё и сходящаяся до wei дельта баланса.
`acceptClaim`, `resolveVote` и цифры со страницы баунти доказательством не являются.

## Наблюдаемость

| Что | Где |
|---|---|
| Что происходит сейчас | TUI, экран «ДОСКА» и «АГЕНТЫ» |
| О чём договорились | TUI, экран «ПЕРЕПИСКА»; `hermes agora show <id>` |
| Что предложено и ждёт | TUI, экран «ПРЕДЛОЖЕНИЯ» |
| Сколько заработано | TUI, экран «ДЕНЬГИ»; `vault/Агенты/Деньги.json` |
| Визуально | вкладка «Агенты» в дашборде Hermes (`/agents`) |
| Журналы | `vault/Агенты/Журнал - <проект>.md` |

Обновление карты — раз в 2.5 секунды, без перезагрузки страницы.
